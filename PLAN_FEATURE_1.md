# Visual Markdown Editor and Mention Notifications

## Implementation Status

Implemented locally on June 13, 2026.

- Milkdown visual editing, CodeMirror source editing, and the existing preview are available as synchronized modes.
- Document and project-member completion, mention highlighting, drafts, validation, conflicts, and save shortcuts are integrated.
- Document writes record `updatedBy`.
- Private mention notifications, navbar controls, Firestore rules, and a Node.js 22 Firebase Function in `europe-west1` are implemented.
- Angular, documentation, Functions, Firestore rules, and production-build validation are included.
- Production deployment of the Function remains intentionally pending and requires the Firebase Blaze plan.

## Summary

Replace the textarea and permanent split view with a three-mode editor:

- **Edit**: default Milkdown visual Markdown editor.
- **Markdown**: CodeMirror 6 source editor.
- **Preview**: existing Markdown and PlantUML renderer.

Add expanded formatting controls, `#` document completion, `@` project-member completion, and secure in-app mention notifications generated by a Firebase Function.

## Editor Changes

- Add Milkdown 7 with GFM support for visual editing and CodeMirror 6 for source editing.
- Keep one canonical Markdown string synchronized between modes; lazy-create editor instances and destroy them with the Angular component.
- Preserve GFM tables, relative links, fenced code languages, PlantUML blocks, drafts, validation, conflict handling, and `Ctrl/Cmd+S`.
- Add a toolbar with paragraph/H2-H4, bold, italic, lists, link, inline code, code block, quote, horizontal rule, undo, redo, and search.
- Do not offer H1 creation in the toolbar. The existing filename-matching H1 remains editable and validated.
- Search opens the CodeMirror search/replace panel, switching to Markdown mode when necessary.
- Apply Manuscript light/dark themes and accessible labels, focus handling, keyboard navigation, and mobile mode tabs.
- Fix the malformed `Â·` editor-toolbar separator.

## Completion and Mentions

- `#query` suggests project documents in visual and source modes.
  - Selecting one inserts a normal Markdown link with an encoded relative path.
  - Markdown heading syntax such as `# Title` must not trigger completion.
- `@query` suggests project members by Firebase UID.
  - Persist mentions as portable plain `@firebaseUid` text.
  - Decorate valid project-member mentions visually without changing stored Markdown.
- Allow authenticated members of an active project to list that project’s member UIDs and roles; anonymous users and members of other projects remain denied.
- Load members for owners and editors, then pass document and member completion data into the editor.

## Notifications and Firebase

- Add a private notification model under `users/{uid}/notifications/{notificationId}` containing mention type, recipient UID, actor UID, project ID/name/slug, document path/title/version, creation time, and read state.
- Add `updatedBy` to document saves and require it to equal the authenticated UID. Existing documents require no migration; they gain the field on their next save.
- Add a Node.js 22 Firebase Function in `europe-west1`, close to the `eur3` Firestore database.
  - Trigger on project-document creation/update.
  - Compare old and new `@UID` sets.
  - Notify only newly added valid project members.
  - Ignore self-mentions.
  - Use deterministic notification IDs so trigger retries are idempotent.
  - Re-adding a previously removed mention creates a new notification on the later version.
- Add a navbar bell for signed-in users with unread count, recent notifications, and “Mark all read.”
- Selecting a notification marks it read and opens the referenced project/document through a `document` query parameter; canonical slug correction preserves that parameter.
- Firestore Rules allow recipients to read notifications and update only their read state. Clients cannot create or delete notifications.
- Add Functions configuration and emulator support to `firebase.json`; production deployment requires upgrading the Firebase project to Blaze before deploying the function.

## Tests and Validation

- Editor tests: visual/source/preview switching, Markdown round trips, formatting commands, search transition, themes, mobile behavior, large documents, draft recovery, validation, save shortcuts, and conflicts.
- Completion tests: relative paths, encoded spaces, heading exclusion, UID filtering, keyboard selection, and no suggestions from unrelated projects.
- Function tests: new mentions, unchanged mentions, removed/re-added mentions, self-mentions, invalid members, multiple recipients, and retry idempotency.
- Rule tests: project-member directory visibility, notification privacy, denied client creation/deletion, restricted read-state updates, and `updatedBy` enforcement.
- Regression tests: PlantUML fences, GFM tables, internal-link validation, navigation warnings, and Firestore version transactions.
- Run Angular tests, documentation tests, Functions tests, Firestore emulator tests, production build, and manual desktop/mobile accessibility checks.

## Assumptions

- User mentions provide in-app notifications only; no email or push notifications.
- UIDs are the visible identity until roadmap membership onboarding introduces email/display-name profiles.
- Real-time collaborative editing remains out of scope.
- Milkdown is the visual editor; CodeMirror is the authoritative source-mode editor.
- The existing uncommitted roadmap and README link remain part of the work and are updated to reflect completion.
